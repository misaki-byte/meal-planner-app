# まいにちの台所

家族のレシピ・今週の献立・お店別の買い物リストをまとめる、日本語のスマートフォン向けWebアプリです。Next.js App Router / TypeScript / Tailwind CSS / Supabaseを使用します。有料APIは使用しません。

## 使える機能

- **レシピ帳**：追加・編集・削除、料理名・食材検索、家族ウケ度★1〜5、作り方メモ、基準人数と食材の分量・単位・カテゴリ。人数の初期値は4人、人数に応じた換算に対応。
- **今週の献立**：レシピから複数選択、同じ料理の重複選択、料理ごとの人数・調理チェック。5〜6品を目安に、品数の強制制限はありません。
- **週の切り替え**：今週の献立と買い物を履歴に保存し、未調理の料理・未購入の商品だけを引き継ぎます。履歴は自動削除しません。
- **買い物リスト**：食材名と単位が一致する数量を合算、お店別タブとカテゴリ表示、購入チェック、お店・カテゴリ変更、手動商品の追加・編集・削除。
- **店舗管理**：カネスエ・業務スーパー・100均・コストコを初期登録。追加・編集・削除に対応。店舗削除後も商品は残ります。
- **永続保存**：Supabase Authによるメール・パスワード認証、確認メール、パスワード再設定、RLS。アカウントごとにDBへ自動保存。同一アカウントで別端末から利用できます。
- **スマートフォン対応**：画面下のナビ、大きな購入チェック、PWA、ホーム画面用アイコン、安全領域への対応。
- **準備と保管**：接続前の設定ガイド、保存しないサンプルモード、JSONによるデータ書き出し。

## 初めての設定

**[日本語セットアップガイド](docs/SETUP.md) に、初回設定から公開までの手順があります。**

```sh
npm ci
cp .env.example .env.local
```

1. Supabaseの無料プロジェクトを作成します。
2. SQL Editorで [supabase/schema.sql](supabase/schema.sql) を全て実行します。
3. `.env.local` にプロジェクトURLと公開用Publishable keyを設定します。

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
```

4. Supabase AuthenticationのSite URLとRedirect URLsに `http://localhost:3000` を設定します。
5. `npm run dev` を実行し、`http://localhost:3000` を開きます。
6. 新規登録して確認メールを開き、ログインします。

公開用キーはRLSと組み合わせてブラウザで使うためのキーです。**Secret key / service_role key / DBパスワードを環境変数に設定しないでください。** 従来の公開用 `NEXT_PUBLIC_SUPABASE_ANON_KEY` も読み込めますが、新規設定は上記を推奨します。

環境変数が未設定でもガイドとサンプルモードを開けます。サンプルはメモリ内だけで動作し、再読込・終了で消えます。本番データとは混ざりません。

## 開発・検証

Node.js 22以上、npmを使用します。

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Linuxで既存のChromiumを使用する場合：

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

テストは献立の重複・換算・買い物の状態保持・週切替・履歴、実際のSQLをPostgreSQL互換環境（PGlite）で実行するRLSと競合制御、スマホ幅のブラウザ操作とPWAを確認します。GitHub Actionsでも型・テスト・ビルド・ブラウザテストを実行します。

## データ保存の仕組み

- 各アカウントの状態を `planner_data` のJSONB文書1行へ保存します。レシピ・献立・買い物・履歴を一括保存するので、週切替の途中だけが保存されることを防ぎます。
- `save_planner` RPCはログイン中の `auth.uid()` を使います。RLSが別アカウントの参照・書換えを拒否します。
- 保存時に `revision` の一致を確認します。別端末で先に更新された場合は保存を拒否し、再読込を案内します。操作は最新データでやり直してください。無断で古い文書を上書きしません。
- 保存成功後に画面へ反映します。通信失敗時は保存完了と表示せず、再読込による確認を案内します。
- 献立にはレシピの登録時点の写しを持ちます。レシピ帳を編集・削除しても、献立と履歴は変わりません。
- 自動集計と手動追加を区別し、献立の再計算で手動商品を消しません。同じ食材でも手動追加した商品は別行です。
- 翌週へ持ち越す未調理料理の購入済み食材は、購入済みの分量として記録します。再購入を防ぎ、人数を増やしたときだけ不足分を追加します。調理済み料理の未購入食材も持ち越します。
- チェック済みの自動食材が増量されたら、買い忘れ防止のためチェックを外します。数量は小数点以下4桁まで丸め、単位変換（gとkg、大さじとml等）は行いません。「適量」は数量1・単位「適量」として登録できます。
- アプリの家庭データはlocalStorageへ保存しません。Supabase SDKがログイン状態を維持するためにブラウザへ保存する認証セッションは別です。
- PWAは公開アイコンとオフライン案内のみキャッシュします。認証済みHTML・家庭のデータ・Supabase APIはキャッシュしません。保存・読み込みには通信が必要です。

詳しい設計・実機での確認項目は [docs/OPERATIONS.md](docs/OPERATIONS.md) を参照してください。
